# Memory Hub

ส่วนขยายของ SillyTavern ที่รวมระบบความจำของแชทยาวไว้ในที่เดียว ใช้แทน Summarize + Memory Books + Vector Storage ได้ โดยไม่ต้องตั้งค่า vector และตั้งใจให้กินโทเคนน้อยที่สุด

## ทำงานยังไง

1. **สรุปเป็นก้อน ไม่สรุปทุกเทิร์น** — ทุก ๆ N ข้อความ (ค่าเริ่มต้น 20) ข้อความเก่าที่สุดที่ยังไม่ถูกสรุปจะถูกสรุปเป็น "ความจำ" หนึ่งก้อน มีชื่อ คีย์ และสรุปเป็นข้อ ๆ การเรียกครั้งเดียวกันนี้อัปเดต "เรื่องย่อจนถึงตอนนี้" ไปด้วย จึงเรียก API แค่ครั้งเดียวต่อ 20 ข้อความ
2. **ไม่ส่งข้อความที่สรุปแล้ว** — ข้อความที่สรุปแล้วจะถูกตัดออกจาก prompt ส่งเต็มแค่ข้อความล่าสุด (ค่าเริ่มต้น 12–32 ข้อความ) แชทจริงไม่ถูกลบหรือซ่อน ปิดส่วนขยายเมื่อไหร่ก็กลับมาเป็นแบบเดิม
3. **ดึงเฉพาะความจำที่เกี่ยวข้อง** — ทุกเทิร์นจะใส่
   - เรื่องย่อหนึ่งก้อน
   - ความจำก้อนล่าสุด (ให้ต่อเนื่องกับข้อความดิบ)
   - ความจำที่ปักหมุดไว้
   - ความจำที่เกี่ยวกับสิ่งที่กำลังคุยอยู่มากที่สุด ไม่เกิน 3 ก้อน

   ทั้งหมดอยู่ภายใต้งบโทเคนที่ตั้งไว้

### Prompt สรุปแบบโมดูล

prompt สรุปประกอบจาก**พื้นฐาน** (เหตุการณ์ การตัดสินใจ คำสัญญา ปมที่ค้าง) บวก**โมดูล**ที่เลือกให้บอทแต่ละตัว แต่ละโมดูลเพิ่มสิ่งที่ต้องจำ สิ่งที่ข้ามได้ คำแบบไหนควรเป็นคีย์ และหัวข้อในเรื่องย่อ

| โมดูล | เพิ่มอะไร |
|---|---|
| ความสัมพันธ์ / โรแมนซ์ | ความรู้สึก ความไว้ใจ จุดเปลี่ยนของความสัมพันธ์ สิ่งที่รู้เกี่ยวกับกัน ชื่อเล่น ของขวัญ |
| หลายตัวละคร | จำแยกทีละตัว ความสัมพันธ์ระหว่างตัวละครด้วยกัน ใครอยู่ที่ไหน |
| เนื้อเรื่อง / ดราม่า | จุดหักมุม แรงจูงใจ การปูเรื่อง ปมที่ยังเปิดอยู่ |
| ปริศนา / ความลับ | เบาะแส ผู้ต้องสงสัย ใครรู้อะไร ใครโกหก |
| ระบบเกม / RPG | เควส ไอเท็ม เงิน สเตตัส สกิล ปาร์ตี้ (ข้ามการต่อสู้ทีละจังหวะ) |
| โลก / การเมือง / ฝ่าย | ฝ่ายต่าง ๆ กฎของโลก ประวัติศาสตร์ สถานที่ |
| ชีวิตประจำวัน | กิจวัตร ตารางเวลา นัดหมาย ความชอบเล็ก ๆ |
| เอาชีวิตรอด / สยองขวัญ | บาดแผล ทรัพยากร ภัยคุกคาม ใครตาย ใครหาย |
| เวลาในเรื่อง | วัน เวลา การข้ามเวลา เส้นตาย |
| แผงสเตตัส / ค่าความชอบ | จำเฉพาะค่าล่าสุดที่สำคัญ ไม่จำตัวแผง |

**บอทได้โมดูลจากไหน**
1. **แท็กของการ์ด** — ติ๊กโมดูลในแผงตั้งค่า (ส่วน "โมดูลของบอทนี้") หรือกด ＋/× บนแถบด้านบน Memory Hub จะแปะแท็กของโมดูลนั้นให้การ์ด เช่น `rpg`, `multiple characters`, `story` และเอาแท็กของโมดูลที่ไม่เลือกออก
   - แท็กถูกเขียนลง **ไฟล์การ์ด** ด้วย ไม่ใช่แค่ในเครื่องนี้ ย้ายเครื่อง ย้ายแอพ หรือแชร์การ์ด ก็ได้โมดูลชุดเดิม ความจำที่สรุปจากคนละเครื่องจึงออกมาแบบเดียวกัน
   - การ์ดที่มีแท็กอยู่แล้ว เช่น `RPG`, `romance`, `โรแมนซ์`, `mystery`, `สยองขวัญ` จะเปิดโมดูลให้เองโดยไม่ต้องทำอะไร (ชี้เมาส์ที่โมดูลเพื่อดูว่าแท็กไหนใช้ได้)
   - ไม่เลือกโมดูลเลย = แท็ก `memhub-basic` (ใช้แค่พื้นฐาน)
   - "กลับไปใช้ค่าเริ่มต้น" = เอาแท็กของโมดูลออกจากการ์ด
2. **แชทกลุ่ม** — กลุ่มไม่มีไฟล์การ์ด ที่เลือกไว้จึงเก็บในเครื่องนี้ (หรือใส่แท็กให้กลุ่มใน SillyTavern)
3. **ค่าเริ่มต้น** — ใช้เมื่อการ์ดไม่มีแท็กของโมดูลเลย แชทเดี่ยวใช้ "ความสัมพันธ์" แชทกลุ่มใช้ "หลายตัวละคร + เนื้อเรื่อง" หรือกด "ตั้งชุดนี้เป็นค่าเริ่มต้น" เพื่อเปลี่ยน ค่าเริ่มต้นเก็บแยกในแต่ละเครื่อง ถ้าใช้หลายเครื่องให้เลือกโมดูลให้การ์ดไว้เลยจะเสถียรกว่า

ถ้าอัปเดตจากเวอร์ชันก่อน 1.8.0: โมดูลที่เคยเลือกให้ตัวละครไว้ในเครื่องนี้ จะถูกย้ายไปเป็นแท็กบนการ์ดเองตอนเปิดแชทของบอทนั้น (มีแจ้งว่าเพิ่ม/เอาแท็กไหนออก)

โมดูลที่สร้างเอง (จัดการโมดูล / สร้างเอง) เก็บในเครื่องนี้ ถ้าใช้ที่เครื่องอื่นต้องสร้างโมดูลชื่อและแท็กเดียวกันไว้ด้วย ไม่งั้นเครื่องนั้นจะไม่รู้จักแท็กนั้น

ตัวอย่าง: บอทสายเนื้อเรื่องที่มีหลายคาร์ ติ๊ก **หลายตัวละคร + เนื้อเรื่อง** (บวก ปริศนา ถ้ามีความลับเยอะ)

- ความยาวของความจำและเรื่องย่อขยายตามโมดูลที่เลือกอัตโนมัติ (ปิดได้) งบโทเคนของความจำที่ดึงก็ขยายตามสัดส่วนเดียวกัน จึงยังดึงได้จำนวนก้อนเท่าเดิม ตัวเลขจริงของบอทนี้แสดงใต้รายการโมดูล
- ชี้หรือแตะที่โมดูลเพื่อดูว่าโมดูลนั้นจำอะไร เหมาะกับบอทแนวไหน และแท็กไหนเปิดให้เอง
- บนแผงที่คั่นหนังสือ (แถบด้านบนของแชท) จะเห็นว่าแชทนี้ใช้โมดูลอะไรอยู่ กด × เพื่อเอาออก หรือเลือก "＋ เพิ่ม" ได้ทันทีโดยไม่ต้องเข้าหน้า Extensions
- **ดู prompt ที่ประกอบแล้ว** เพื่อเช็กว่าบอทนี้จะได้ prompt แบบไหน
- **จัดการโมดูล / สร้างเอง** — สร้างโมดูลของเราเอง (เช่น "ตำรวจ": เลขคดี, หลักฐาน, ใครดูแลคดีไหน) ใส่แท็กให้เปิดอัตโนมัติได้ หรือกด "แก้ไข" ที่โมดูลในตัวเพื่อทำฉบับของเราแทน
- ถ้าอยากเขียนทั้ง prompt เอง เลือกแบบ "เขียนเองทั้งหมด" (จะเริ่มจาก prompt ที่ประกอบแล้วของบอทที่เปิดอยู่)

prompt สรุปถูกส่งแยกจากพรีเซตแชท: main prompt, jailbreak, prefill และเอนทรี lorebook ไม่ถูกใส่ไปด้วย ที่ติดไปมีแค่ค่าการสุ่ม (temperature ฯลฯ) ของ API/พรีเซตนั้น

### API สำรอง

ตั้งลำดับ API ที่ใช้สรุปได้หลายตัว เช่น 1. Google AI Studio 2. DeepSeek 3. API หลัก ถ้าตัวแรก error, ไม่ตอบภายในเวลาที่ตั้ง, ตอบว่าง (โดน safety filter/โควต้าหมด) หรือตอบผิดรูปแบบ จะลองตัวถัดไปเอง และขึ้นเตือนว่าสลับไปใช้ตัวไหน ถ้าพังหมดทุกตัวจะขึ้น error พร้อมเหตุผลของแต่ละตัว สถานะล่าสุดดูได้ในแผงตั้งค่า

API สำรองคือ Connection Profile — สร้างที่แท็บ API Connections แล้วกด Connection Profile → สร้างใหม่ ทีละตัว

หลังพังแบบอัตโนมัติ ระบบจะเว้น 4 ข้อความก่อนลองใหม่ เพื่อไม่ให้เด้งเตือนทุกข้อความ กด "สรุปตอนนี้" เพื่อลองทันที

### แตกกิ่ง (branch)

SillyTavern คัดลอกความจำไปให้กิ่งใหม่ด้วย Memory Hub จะตรวจเองว่าความจำก้อนไหนครอบคลุมข้อความหลังจุดแตกกิ่ง แล้วถอดออก เรื่องย่อจะย้อนกลับไปเป็นฉบับที่ใช้อยู่ ณ จุดนั้น ส่วนที่ถอดออกจะถูกสรุปใหม่จากเนื้อเรื่องของกิ่งเอง ความจำของกิ่งเดิมไม่ถูกแตะ

(ความจำที่สร้างในเวอร์ชัน 1.0.0 ไม่มีเรื่องย่อฉบับย้อนหลังเก็บไว้ ถ้าแตกกิ่งจากช่วงนั้น ให้กด "สร้างเรื่องย่อใหม่")

### เริ่มแชทใหม่ต่อเรื่องเดิม

ปุ่ม **เริ่มแชทใหม่ต่อเรื่อง** (หรือ `/memhub-continue`)
1. สรุปข้อความที่ยังค้างให้หมดก่อน (ปิดได้)
2. สร้างแชทใหม่กับตัวละคร/กลุ่มเดิม
3. เปลี่ยนข้อความแรกของแชทใหม่เป็นข้อความล่าสุดของบอทจากแชทเดิม
4. พกความจำทั้งหมดและเรื่องย่อไปด้วย ต่อกันเป็นทอด ๆ ได้ไม่จำกัด

แชทใหม่เริ่มสั้น ประหยัดโทเคน และโหลดเร็ว แชทเดิมไม่ถูกแก้ไข ถ้าต่อแชทใหม่เองด้วยมือ ใช้ **นำเข้า → จากแชทอื่น** ดึงความจำมาต่อได้เหมือนกัน

### ทำไมไม่ติดทุกเอนทรีแบบ lorebook

lorebook ใช้การติดคีย์เวิร์ด ถ้าคีย์เป็นชื่อตัวละครซึ่งมีแทบทุกข้อความ ก็จะติดทุกครั้ง

Memory Hub ใช้การให้คะแนนแบบ BM25 แทน คำที่มีในความจำเกือบทุกก้อน เช่น ชื่อตัวหลัก จะได้น้ำหนักแทบเป็นศูนย์โดยอัตโนมัติ ความจำจะถูกดึงก็ต่อเมื่อมีคำที่เฉพาะเจาะจง เช่น สถานที่ สิ่งของ หรือเหตุการณ์ ถ้ากำลังคุยเล่นทั่วไป ก็จะไม่ดึงอะไรเพิ่ม

ภาษาไทยตัดคำด้วยตัวตัดคำของเบราว์เซอร์ (`Intl.Segmenter`) ปัญหาคีย์ `ยา` ไปติดใน `พยายาม` จึงไม่เกิด ไม่ต้องใช้ embedding หรือเซิร์ฟเวอร์เพิ่ม และไม่เสีย API ในขั้นตอนนี้

## ติดตั้ง

Extensions → Install extension → วาง URL ของ repo นี้

แล้ว**ปิดตัวที่ทำหน้าที่ซ้ำ** ไม่งั้นจะเสียโทเคนสองทาง
- Summarize ของ SillyTavern: กด Pause หรือปิดส่วนขยาย (ถ้ายังส่งอยู่ Memory Hub จะขึ้นเตือน)
- Memory Books / lorebook ความจำเดิม: นำเข้ามาก่อน (ดูด้านล่าง) แล้วถอด lorebook นั้นออกจากแชท
- Vector Storage สำหรับแชท: ปิดได้

ทดสอบกับ SillyTavern 1.19.0

## ใช้งาน

แทบไม่ต้องทำอะไร คุยไปตามปกติ เมื่อข้อความครบรอบ ระบบจะสรุปเอง

### โหมดการสรุป

เลือกได้ที่ Extensions → Memory Hub → **การสรุป**

| โหมด | ทำงานยังไง | เหมาะกับ |
|---|---|---|
| **อัตโนมัติ** (ค่าเริ่มต้น) | สรุปเองทุก ๆ N ข้อความ (ตั้งได้ที่ "สรุปทุก ๆ") | คนส่วนใหญ่ ไม่ต้องคิดอะไร |
| **กึ่งอัตโนมัติ** | ครบ N ข้อความจะขึ้นหน้าต่างถามก่อน กด "สรุปเลย" หรือ "ยังก่อน" แล้วเลือกว่าจะให้ถามอีกครั้งในอีกกี่ข้อความ | อยากรอให้ฉากจบก่อนค่อยสรุป |
| **สรุปเอง (Manual)** | ไม่สรุปเอง กด "สรุปเดี๋ยวนี้" เมื่อต้องการ | อยากคุมเองทั้งหมด |

**ความยาวขยายตาม N** — ถ้าตั้งให้ความจำหนึ่งก้อนครอบคลุมข้อความมากกว่า 20 ข้อความ ความยาวความจำและงบความจำที่ดึงจะขยายตามสัดส่วน (เช่น 40 ข้อความ = ยาวขึ้น 2 เท่า) ตัวเลขจริงแสดงใต้รายการโมดูล ปิดได้ด้วยช่อง "ขยายความยาว…อัตโนมัติ"

**ข้อควรรู้ของโหมด Manual** (ตอนเลือกโหมดนี้จะมีหน้าต่างอธิบายและถามเรื่องโควต้า)
- ข้อความที่ยังไม่สรุปถูกส่งแบบเต็มทุกเทิร์น ยิ่งค้างมาก ยิ่งเปลืองโทเคน
- ถ้าค้างจนเกิน context ของโมเดล ข้อความเก่าสุดจะหลุดจาก prompt บอทลืมช่วงนั้นจนกว่าจะสรุป
- กดสรุปทีเดียวหลายร้อยข้อความ = เรียก API หลายรอบติดกัน ใช้เวลานาน และอาจชนโควต้าของ API ฟรี
- **ตัวคูณโควต้าความจำ** (×1 / ×1.5 / ×2 / ×3) ทำให้ความจำแต่ละก้อนละเอียดขึ้น แลกกับ prompt ที่ยาวขึ้น
- เมื่อค้างเกิน 40 ข้อความ (หรือ 2 เท่าของ N) จะมีแจ้งเตือน ตัวเลขบนปุ่มแถบด้านบนเป็นสีแดง และแผงขึ้นเตือนพร้อมปุ่มสรุปเลย โหมดกึ่งอัตโนมัติก็เตือนแบบเดียวกันถ้าเลื่อนไปเรื่อย ๆ

### ตั้งค่าตามแบบที่ใช้

**เริ่มใช้ครั้งแรก / เปิดแชทเก่าที่ยาวอยู่แล้ว**
- กด **สรุปตอนนี้** ครั้งเดียว ระบบจะสรุปข้อความเก่าย้อนหลังจนครบ
- กด **ดูสิ่งที่ส่งล่าสุด** เพื่อเช็กว่ามีเรื่องย่อและความจำถูกส่งไปจริง

**คุยยาวในแชทเดียว** — ใช้ค่าเริ่มต้นได้เลย

**ขึ้นแชทใหม่ทุก ~60 ข้อความ**
- ค่าเริ่มต้น (ทุก 20 ข้อความ) ลงตัวพอดี แชทหนึ่งได้ความจำ 3 ก้อน
- ขึ้นแชทใหม่ด้วยปุ่ม **สรุป + ขึ้นแชทใหม่** เสมอ อย่ากด New Chat ของ SillyTavern เอง
- ถ้าปรับ N ให้เลือกค่าที่หารจำนวนข้อความต่อแชทลงตัว เช่น 15 / 20 / 30

**ชอบละเอียด เลือกหลายโมดูล**
- ความยาวความจำ เรื่องย่อ และงบความจำที่ดึง ขยายตามโมดูลให้เอง
- เรื่องย่อถูกส่งทุกเทิร์น เลือก 5–6 โมดูลอาจเพิ่มราว 2000–3000 โทเคนต่อเทิร์น
- โมเดลที่ใช้สรุปต้องตอบได้ยาวพอ (ดู "response" ใต้รายการโมดูล) ถ้าความจำขึ้น ⚠ ไม่ครบบ่อย ให้เอาโมดูลที่ไม่จำเป็นออก หรือใช้โมเดลที่ตอบได้ยาวกว่า
- เลือกเฉพาะแนวที่บอทเป็นจริง ๆ ดีกว่าติ๊กทุกอัน

**อยากประหยัดที่สุด**
- ตั้งโมเดลถูกหรือฟรีเป็น API อันดับ 1 ที่ใช้สรุป
- สรุปทุก 30 ข้อความ และเลือกโมดูล 1–2 อัน
- ลดความยาวเรื่องย่อพื้นฐานลงเหลือ 150

แผงตั้งค่าอยู่ที่ Extensions → **Memory Hub**
- **เปิดคลังความจำ** — ดู แก้ ปักหมุด ลบ หรือสั่งสรุปช่วงใหม่ของแต่ละก้อน และแก้เรื่องย่อได้
- **สรุปตอนนี้** — สรุปทุกข้อความที่ค้างอยู่ ใช้ตอนเปิดแชทเก่าที่ยาวอยู่แล้ว (สรุปย้อนหลังทีละก้อนจนครบ)
- **ดูสิ่งที่ส่งล่าสุด** — ดูว่าเทิร์นที่แล้วใส่อะไรเข้า prompt บ้าง กี่โทเคน ความจำไหนถูกเลือกเพราะคำไหน และประหยัดไปกี่โทเคน

### ปุ่มบนแถบด้านบนของแชท

ถ้าติดตั้ง [Top Info Bar](https://github.com/SillyTavern/Extension-TopInfoBar) (ตัวเดียวกับที่ Memory Books ใช้) จะมีปุ่มที่คั่นหนังสืออยู่หน้าชื่อแชท (เปลี่ยนไอคอนได้ในการตั้งค่า: ที่คั่นหนังสือหัวใจ / ดาว / จันทร์ หรือไอคอนและอีโมจิอื่น) ถ้าไม่มี Memory Hub จะสร้างแถบบาง ๆ ของตัวเองเหนือแชทแทน (ปิดได้ในการตั้งค่า)

- ตัวเลขบนปุ่ม: สรุปแล้วถึงข้อความที่เท่าไหร่ (`#40`) ตอนกำลังสรุปจะเปลี่ยนเป็นความคืบหน้า (`2/5`) และปุ่มจะกะพริบ ถ้าล้มเหลวตัวเลขเป็นสีแดง
- ปรับหน้าตาป้ายตัวเลขได้ในการตั้งค่า (ใต้ไอคอน)
  - แบบ: ป้ายมีขอบ / ป้ายไม่มีขอบ / ตัวเลขแทนไอคอน (ฟอนต์ monospace ของธีม จัดกลางแนวตั้ง ขนาดใหญ่สูงเท่าไอคอน ไอคอนกลับมาเมื่อยังไม่มีตัวเลข) / ไม่แสดง
  - ตำแหน่ง: ขวาล่าง / ขวาบน / ซ้ายล่าง / ตรงกลาง
  - สี: ตามธีม (สีตัวหนังสือหลัก, Quote, Em, ขีดเส้นใต้ ของ SmartTheme) หรือเลือกเองทั้งสีตัวเลขและสีพื้น
  - ขนาด: เล็ก / กลาง / ใหญ่
- กดปุ่มเพื่อเปิดแผง:
  - สรุปแล้วถึงข้อความไหน จากทั้งหมดเท่าไหร่ ค้างอยู่กี่ข้อความ และรอบอัตโนมัติถัดไปจะเริ่มที่ข้อความไหน
  - คิวงาน: กำลังสรุปช่วงไหน ก้อนที่เท่าไหร่จากทั้งหมด ใช้ API ตัวไหน (และตัวที่เท่าไหร่ในรายการสำรอง) มีปุ่มหยุด และงานที่รอคิว
  - ผลล่าสุด สำเร็จหรือล้มเหลวพร้อมเหตุผล และปุ่ม "ลองตอนนี้" ถ้าการสรุปอัตโนมัติพักไว้หลังล้มเหลว
  - ปุ่ม **สรุปเดี๋ยวนี้**, **สรุป + ขึ้นแชทใหม่**, **คลังความจำ**, **ส่งอะไรไปล่าสุด**

### คำตอบถูกตัด

โมเดลแบบ "คิดก่อนตอบ" (เช่น Gemini 2.5) ใช้โทเคนไปกับการคิด บางทีคำตอบสรุปจึงถูกตัดกลางประโยค Memory Hub ตรวจเองว่าคำตอบจบครบไหม ถ้าไม่ครบจะลองใหม่ด้วยเพดานสองเท่า แล้วค่อยไป API ถัดไป ถ้าทุกตัวยังตอบไม่จบ จะเก็บเท่าที่ได้ไว้ก่อนแล้วติด **⚠ ไม่ครบ** ที่ความจำก้อนนั้น เพิ่ม Response length แล้วกด 🔄 เพื่อสรุปใหม่

### ส่งออกคลังความจำ

คลังความจำ → **ส่งออก** (หรือ `/memhub-export`)
- **Markdown** อ่านง่าย: เรื่องย่อ ความจำทุกก้อน (ช่วงข้อความ คีย์ และย่อจากกี่โทเคนเหลือกี่โทเคน) สถิติรวม และ prompt สรุปที่ใช้อยู่
- **JSON** ข้อมูลเดียวกันแบบเต็ม นำเข้ากลับได้ที่ นำเข้า → จากไฟล์ (ใช้ย้ายความจำข้ามเครื่องหรือเก็บสำรอง)
- ติ๊ก **แนบข้อความต้นฉบับ** เพื่อวางข้อความเดิมไว้ใต้ความจำแต่ละก้อน เอาไว้เทียบว่าสรุปตกหล่นอะไร หรือจำเรื่องไม่จำเป็นเกินไปไหม

คำสั่ง `/memhub` เปิดคลังความจำ, `/memhub-now` สั่งสรุปทันที และ `/memhub-continue` เริ่มแชทใหม่ต่อเรื่อง และ `/memhub-export` ส่งออก ใช้ทำปุ่มใน Quick Dock ได้

### นำเข้าของเดิม

ในคลังความจำ กด **นำเข้า**
- **จากแชทอื่น** ของตัวละครนี้: ดึงความจำและเรื่องย่อของ Memory Hub มาต่อ
- **จาก lorebook** (เช่นที่ Memory Books สร้างไว้): ทุกเอนทรีจะกลายเป็นความจำ แล้วถูกดึงตามความเกี่ยวข้องแทนการติดคีย์ เอนทรีที่เป็น constant จะถูกปักหมุด
  - ทำให้เองทุกครั้ง (ไม่เสีย API): ล้าง HTML, ตัดเอนทรีซ้ำ, ลบคีย์ที่เป็นชื่อตัวหลัก (ต้นเหตุที่ทำให้ติดทุกเอนทรี)
  - **จัดระเบียบด้วย AI** (ติ๊กไว้เป็นค่าเริ่มต้น): เอนทรีที่ยาวเกินจะถูกย่อให้กระชับ ตัดข้อความเมตา และทำคีย์ใหม่ ส่งไปครั้งละไม่เกิน 6 เอนทรี แล้วสร้างเรื่องย่อจากทั้งคลังถ้ายังไม่มี เอนทรีที่สั้นอยู่แล้วไม่ถูกส่ง
- **จาก Summarize ในตัว**: ใช้บทสรุปล่าสุดของแชทเป็นเรื่องย่อ

## ประหยัดขึ้นอีก

- **ใช้โมเดลถูก ๆ สรุป** — สร้าง Connection Profile ของโมเดลราคาถูกหรือฟรี แล้วตั้งเป็น API อันดับ 1 ในรายการ API ที่ใช้สรุป แชทยังใช้โมเดลหลัก แต่งานสรุปไปใช้ตัวถูก
- **เพิ่ม "สรุปทุก ๆ"** — ยิ่งมาก ยิ่งเรียก API น้อยครั้ง แต่ข้อความดิบในแต่ละเทิร์นจะยาวขึ้น
- **Prompt caching (Claude และบางเจ้า)** — ค่าเริ่มต้นวางเรื่องย่อไว้ต่อจาก Story string และวางความจำที่ดึงไว้ในแชทที่ depth 2 เพราะส่วนที่เปลี่ยนทุกเทิร์นควรอยู่ท้าย ๆ ไม่งั้น cache จะใช้ไม่ได้ ส่วนข้อความที่ถูกตัดออกจะขยับแค่ตอนสรุปก้อนใหม่ cache จึงคงอยู่ได้ระหว่างนั้น

## ค่าที่ปรับได้

| ค่า | เริ่มต้น | ความหมาย |
|---|---|---|
| การสรุป | อัตโนมัติ | อัตโนมัติ / กึ่งอัตโนมัติ (ถามก่อน) / สรุปเอง |
| สรุปทุก ๆ | 20 | กี่ข้อความต่อความจำหนึ่งก้อน ถ้ามากกว่า 20 ความยาวความจำขยายตาม |
| ถามอีกครั้งในอีก | 10 | โหมดกึ่งอัตโนมัติ: กด "ยังก่อน" แล้วจะถามใหม่หลังจากนี้กี่ข้อความ |
| ตัวคูณโควต้าความจำ | ×1 | คูณความยาวความจำแต่ละก้อนและงบความจำที่ดึง |
| เก็บข้อความล่าสุดแบบเต็ม | 12 | ข้อความใหม่สุดที่ยังไม่สรุป และส่งเต็มเสมอ |
| ความยาวความจำ / เรื่องย่อ | 120 / 250 คำ | ความยาวสูงสุดที่สั่งโมเดล |
| ดึงความจำที่เกี่ยวข้องสูงสุด | 3 ก้อน | ไม่นับก้อนล่าสุดและก้อนที่ปักหมุด |
| งบโทเคนของความจำที่ดึง | 800 | รวมทุกก้อนที่ดึง (ไม่นับเรื่องย่อ) ขยายตามโมดูลเหมือนความยาวความจำ ก้อนที่ปักหมุดและก้อนล่าสุดใส่เสมอแม้เกินงบ |
| ดูบริบทจากข้อความล่าสุด | 4 | ใช้ข้อความล่าสุดกี่ข้อความตัดสินว่าอะไรเกี่ยวข้อง |

ในหมวดขั้นสูงแก้ได้ทั้งตำแหน่งที่ใส่ แม่แบบ และ prompt ที่ใช้สรุป

## ข้อมูลเก็บที่ไหน

เก็บใน metadata ของแชท ไฟล์แชทจึงพกความจำไปด้วย ถ้าแตก branch หรือคัดลอกแชท ความจำจะติดไปด้วย และใช้ได้ทุกเครื่องที่เปิดแชทนั้น

ถ้าลบข้อความท้ายแชทจนเลยช่วงที่สรุปไว้ ความจำของช่วงนั้นจะถูกถอดและสรุปใหม่เอง ถ้าแก้หรือลบข้อความกลางแชทที่สรุปไปแล้ว ให้กดไอคอน 🔄 ที่ความจำก้อนนั้นเพื่อสรุปใหม่
